# machin3d-overlay 3.2.0

Snapmaker U1 release. The camera now works without pairing, the remaining
time no longer counts up, and print totals come from the slicer metadata
instead of being extrapolated. No breaking changes — every CLI flag,
subcommand and HTTP route from 3.1.0 keeps working.

## Camera: pairing is now optional

Arming the U1's camera daemon no longer requires `snap-pair`. From a LAN
address the overlay drives Moonraker's own `camera.*` JSON-RPC repeater on
`ws://HOST/websocket`, which needs no certificate and no API key because the
U1 ships the private address ranges in Moonraker's `trusted_clients`.

The paired mTLS MQTT control plane is still tried first and still works; the
repeater is the fallback when there is no token, or when the mTLS session
cannot be opened. Pair only if you have narrowed `trusted_clients`, turned on
forced API-key auth, or want the same credentialed path Snapmaker Orca uses.

The daemon also disarms monitor mode roughly six minutes after the last
request, which used to leave long streams frozen on a stale frame. The video
worker now re-arms every two minutes while a viewer is connected and stops
monitor mode on the way out.

`U1_WEBCAM_PROTOCOL.md` documents the whole protocol — both transports, the
watchdog, and the poll URL quirk.

## Accurate remaining time and print totals

Klipper reports no ETA of its own, so the remaining time is extrapolated from
`print_stats.print_duration` over the progress fraction. That extrapolation is
now re-derived **only when progress actually moves**: the slicer's `M73` steps
minutes apart, and recomputing in between made the remaining time count *up*
at several times real speed. Below 1% progress the estimate is withheld
entirely rather than shown as a nonsense number — consumers of
`/api/current-print` may see a null there where 3.1.0 returned a value.

Total print time, filament weight and start time now come from the slicer
metadata (`server/files/metadata`), fetched once per job and retried every 30s
while Moonraker has not parsed the file yet. `estimated_time` is a constant
for the job, so those fields no longer wobble between updates.

## Overlay

- Durations render as hours and minutes only (`9h 41m`, `1h`, `<1m`). Neither
  an estimate nor a remaining time is accurate to the second, and the seconds
  field rewrote itself on every update for no information gain.
- The vertical overlay fits five spools per row when an external spool is
  present, so an AMS plus the external feeder no longer wraps to a second row.

## Bambu

- Thumbnail extraction also looks for files in the archive root, not only in
  the expected subdirectory.

## Internals (no user-visible behavior change)

- The Snapmaker backend is now a generic Moonraker backend (`src/snapmaker/`
  → `src/moonraker/`). Everything U1-specific — mTLS pairing and the camera
  control plane — is quarantined under `moonraker/u1/` and
  `video/u1_camera.rs`; the rest would drive any conformant Moonraker printer,
  except the camera poll URL, which is still the U1's legacy `monitor.jpg`
  path rather than a `/server/webcams/list` lookup.
- Moonraker metadata fetching lives in one place (`moonraker/metadata.rs`),
  shared by the live report path and the thumbnail path.
