# bambu-overlay 2.0.0

This release is a large internal overhaul that reshapes the service's startup,
lifecycle, and state-management contracts. The overlay's externally observable
behavior changes in a handful of ways noted below; the rest is cleaner, more
robust internals.

## Breaking changes

- **`mqtt.connected` JSON field renamed to `mqtt.anyConnected`.** Visible on
  `GET /api/current-print` and on the `/api/current-print/events` SSE stream.
  The bundled overlay JavaScript never read this field — it uses per-device
  `serviceConnected` already — so the shipped overlay is unaffected. Third-party
  consumers of the JSON should update their field name. The semantics are
  unchanged: the flag is `true` when *at least one* MQTT connection is up.
- **Library API:** `bambu_overlay::bambu::CloudDevice::access_code` and
  `LoginResponse::access_token` / `refresh_token` are now `Option<Secret<String>>`
  rather than `Option<String>`. A new `bambu_overlay::secret` module exposes
  `Secret<T>`, which redacts itself from `Debug` and `Display`. Most users will
  not touch these types directly; embedders that did need to call `.expose()` to
  obtain the inner `&str`.

## Reliability and UX improvements

- Overlay state stays coherent through MQTT reconnects: stale catalog data no
  longer repopulates live print/AMS fields during disconnects, and the connection
  bubble correctly reflects per-device state during connecting / disconnected.
- Retained MQTT reports no longer drive live overlay state; only fresh
  non-retained reports for the currently-connected session count.
- The active-print thumbnail clears immediately when there is no current print
  (previously it could linger from a finished job).
- `serve` shuts down cleanly even when SSE or MJPEG clients are still
  connected. Previously open long-lived requests could keep the process alive
  past the shutdown signal.
- The CLI fails fast when the cached Bambu Cloud token has already expired
  (with a clear "run `bambu-overlay login` again" message) instead of failing
  on the first API call.
- Duplicate `--video-device` arguments that resolve to the same device ID are
  rejected at startup.
- Thumbnail fetches are bounded by a small semaphore; the service no longer
  fans out unbounded concurrent downloads when many task transitions arrive at
  once. Duplicate fetches for the same task are coalesced.
- The `/thumbnail` and `/devices/{id}/thumbnail` responses set cache-control
  headers that prevent client-side caching, so the overlay always sees the
  latest thumbnail for the current task.
- MQTT reports for devices not in the configured catalog are ignored rather
  than creating orphan state.
- Cloud thumbnail download URLs are redacted from logs (the URL contains
  short-lived signed credentials).
- Local FTPS thumbnail retrieval tries both `/cache/` and `/model/` paths so
  cloud prints saved under non-deterministic paths still resolve.

## Security and credential hygiene

- All credentials (printer access codes, cloud access tokens) are wrapped in
  `Secret<T>` and render as `<redacted>` in any `Debug` or `Display` output. A
  stray `tracing::warn!(?device, "…")` can no longer leak access codes.
- The per-fetch FTPS CN check has been removed. It performed a separate TLS
  handshake whose verified cert did not bind the subsequent login connection
  (TOCTOU). suppaftp 8.0.3 does not expose the peer cert of an open implicit
  FTPS connection, and Bambu device certificates are X.509 v1 which rules out
  switching to rustls. The startup MQTT certificate check still gates device
  identity; FTPS now relies on the BBL CA chain only. Under the home-LAN
  threat model the per-fetch check was illusory and per-fetch latency drops.

## Internals (no user-visible behavior change)

- `DeviceRegistry` is now mechanically immutable after startup, behind a
  `DeviceRegistryBuilder`.
- The web `AppState` exposes only intent-shaped methods; handlers no longer
  reach through to internal services.
- The thumbnail job state machine is rebuilt around explicit per-device state,
  with snapshot-revision-ordered staleness filtering and pending-replacement
  semantics covered by extensive unit tests.
- MQTT runtime drops a layer of redundant aggregate state; the runtime file is
  split between state mutation and snapshot projection.
- The BBL CA certificate is parsed once at process start, not on every TLS
  handshake.
- `web/current_print` separates its HTTP/SSE handler from the wire-shaped
  payload and value-formatting helpers.
- The video worker watcher is single-use by construction: calling
  `watch_workers` more than once is a compile error rather than a runtime
  deadlock.

## Installation

Pre-built binaries for Linux x86_64, Linux aarch64, and Windows x86_64 are
attached. Verify against `SHA256SUMS`.

For systemd deployments, an example unit lives at
`examples/systemd/bambu-overlay.service`. The token file format is unchanged
from 1.1.0; existing tokens continue to work until they expire.
